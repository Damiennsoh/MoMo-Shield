### Step 2: Add the Audio Engine to your Code
Create a new file called `app/audio_engine.py` (or add this to your `mock_phone.py`). This handles playing the sounds and the voiceover.

```python
import os
import base64
import uuid
import streamlit as st

# --- SOUND EFFECTS ---
def play_sfx(sound_file_name):
    """Plays a local sound effect file using base64 encoding and JS autoplay."""
    file_path = os.path.join("assets", sound_file_name)
    if not os.path.exists(file_path):
        return # Fail silently if file is missing

    with open(file_path, "rb") as f:
        audio_bytes = f.read()
    
    b64 = base64.b64encode(audio_bytes).decode('utf-8')
    mime = "audio/mpeg" if sound_file_name.endswith(".mp3") else "audio/wav"
    uid = uuid.uuid4().hex

    # Inject audio tag into the DOM and trigger play
    audio_html = f"""
        <audio id="{uid}" src="data:{mime};base64,{b64}" autoplay style="display:none;"></audio>
        <script>
            var audio = document.getElementById("{uid}");
            audio.volume = 1.0;
            // Browsers require user interaction to play audio. 
            // Since the user clicked "Play Scenario", this should work.
            audio.play().catch(e => console.log("Audio autoplay blocked:", e));
        </script>
    """
    st.markdown(audio_html, unsafe_allow_html=True)


# --- TEXT-TO-SPEECH (VOICEOVER) ---
def speak_text(text, lang="en-US"):
    """Uses the browser's native SpeechSynthesis API to read text aloud."""
    if not text:
        return
    
    # Escape quotes and newlines for JavaScript
    safe_text = text.replace('"', '\\"').replace('\n', ' ')
    uid = uuid.uuid4().hex

    tts_html = f"""
        <script id="{uid}">
            (function() {{
                // Cancel any currently speaking audio to prevent overlap
                window.speechSynthesis.cancel(); 
                
                let msg = new SpeechSynthesisUtterance("{safe_text}");
                msg.lang = "{lang}"; 
                msg.rate = 1.0;  // Normal speed
                msg.pitch = 1.0; // Normal pitch
                msg.volume = 1.0;
                
                window.speechSynthesis.speak(msg);
            }})();
        </script>
    """
    st.markdown(tts_html, unsafe_allow_html=True)
```

                            let twiMsg = new SpeechSynthesisUtterance("{safe_twi}");

                            window.speechSynthesis.speak(twiMsg);
                        }}, 3000); // Wait 3 seconds for English to finish
                    </script>
                """, unsafe_allow_html=True)

### ⚠️ Important Notes for the Demo

1.  **Browser Autoplay Policy:** Browsers (Chrome/Edge) block audio from playing automatically *unless the user has interacted with the page*. Because the judge or you will click the **"▶ Play Scenario"** button, that counts as interaction, and the audio will work perfectly.
2.  **Twi Voice Accent:** The browser's native TTS does not have a Twi (`tw`) language pack. It will read the Twi text (*"Wɔrehyɛ wo sɛ fa wo PIN kɔ ma!"*) using an English accent. **This is completely fine for a hackathon.** You can explain to the judges: *"In production, we would integrate a dedicated Twi TTS API like Amazon Polly, but for this demo, we are using the browser's native engine to prove the concept offline."*
3.  **Volume Control:** Ensure your laptop volume is up before the demo! 

This addition will make your split-screen demo incredibly powerful. The judge will hear the phone ring, see the scam message, and then immediately hear the sharp alert siren followed by the authoritative voice telling the victim to stop. It creates a visceral reaction that slides alone cannot achieve.

### 2. Can we send REAL SMS or Phone Calls to a real phone using open-source tools?

**Short Answer:** You cannot send *real* cellular SMS or make *real* PSTN (cellular network) calls purely with open-source tools on a laptop without a paid telecom gateway (like Twilio, Arkesel, or Hubtel). Furthermore, **sending unsolicited SMS/calls to random numbers or even judges' phones without explicit consent will violate Act 843 and get you disqualified.**

**However, there is a brilliant, 100% compliant, zero-cost "Hack" to make it feel completely real.**

#### The Winning Workaround: Local VoIP (The "SIP Softphone" Trick)
You can make a **real, ringing phone call** over your local Wi-Fi network to a secondary phone or laptop in the room. It looks, sounds, and feels exactly like a real cellular call, costs $0, requires no telco KYC, and is completely sandboxed.

**How to set it up (Takes 30 minutes):**
1. **On your laptop (The Backend):** Run a lightweight, open-source SIP server like **FreeSWITCH** or **Asterisk** in a Docker container. (There are many 1-command Docker setups for Asterisk on GitHub).
2. **On a secondary phone/laptop (The Victim):** Download a free, open-source SIP softphone app like **Zoiper** or **Linphone** (available on iOS, Android, and Desktop).
3. **Connect them:** Point the Zoiper app on the secondary phone to your laptop's local IP address (e.g., `192.168.1.50`). 
4. **The Demo:** When your Streamlit scenario hits the "Voice Call" step, your Python backend sends a SIP INVITE command to the Asterisk server. **The secondary phone in the room will physically ring.** Your teammate answers it, and the audio streams live.

**Why judges will love this:**
When you say, *"We are now simulating the ingestion of a live voice call,"* and a phone sitting on the judge's table actually rings, it is a massive "wow" moment. It proves your system can intercept real-time signaling without you having to build a fake 5G core.

#### What about Real SMS?
For SMS, the safest and most impressive hackathon trick is the **"Dual-Device Local Webhook"**:
1. Have a secondary phone open to a simple web page hosted on your laptop (e.g., `http://192.168.1.50:8502/sms-simulator`).
2. When your scenario triggers an SMS, your backend pushes the text to that web page via WebSockets.
3. The secondary phone instantly lights up with the fake SMS message in a clean, MTN-branded UI. 
4. *Alternative:* If you really want a *real* SMS, use the free tier of **Twilio** or **Arkesel** (a Ghanaian API), but **you MUST ask the judge for explicit verbal consent first**: *"Judge, for the next step of our demo, I need to send a simulated fraud SMS to your actual phone number. Do you consent to receiving this test message?"* If they say yes, send it. If they say no, fall back to the local webhook trick.
