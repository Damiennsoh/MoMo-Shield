## 🔬 Diagnosis: two bugs stacked together

### Bug 1 — The HTML was emitted without `unsafe_allow_html=True`
Streamlit has two ways to print a string:
- `st.write(html_string)` → **escapes it and shows raw text** (this is what you see).
- `st.markdown(html_string, unsafe_allow_html=True)` → **renders it as HTML/CSS**.

Kimi's code rendered the phone *frame* correctly (so that part used `unsafe_allow_html=True`), but then emitted the **warning block** and the **caption block** as separate `st.write(...)` calls (or separate `st.markdown(...)` calls *missing* the flag). That's why the frame looks like a phone and the warning looks like source code sitting *below* it.

### Bug 2 — A stray `</div>` broke the nesting
Look at your leaked code carefully:

```html
<div class="phone-warning">
  <div class="warn-title">⚠️ FRAUD ALERT — SIKA AFONO AKENKAN</div>
  <div class="warn-body">Yɛn hu sɛ obi rehyɛ wo...</div>
</div>
</div>   <!-- ← THIS EXTRA CLOSING TAG IS THE KILLER -->
<div class="phone-caption">Victim handset...</div>
```

That extra `</div>` closes the **phone-screen container early**, so the caption falls *outside* the phone visual. Even if you fix Bug 1, this stray tag will keep the layout broken. The warning must live **inside** `<div class="phone-screen">`, and the caption **inside** `<div class="phone-frame">`, with correct nesting.

### The root architectural mistake
Kimi split the phone into **multiple separate render calls** (frame here, warning there, caption elsewhere). In Streamlit, each `st.markdown` is its own DOM block, so a warning rendered in a *second* block can never visually sit *inside* the phone frame from the *first* block. **The entire phone must be ONE string, rendered in ONE `st.markdown(..., unsafe_allow_html=True)` call.**

## 🛠️ The Fix (replace the render logic in `components/mock_phone.py`)

Build the whole handset as a single HTML string, with the warning conditionally embedded *inside* the screen, and render it once:

```python
import streamlit as st

def render_mock_phone(state: dict):
    """
    state keys:
      caller, message, action_prompt,
      alert (bool), twi_msg, en_msg,
      tier ('HIGH'|'MEDIUM'|'LOW')
    """
    # 1. The in-screen USSD / call view (what the victim sees)
    screen_inner = f"""
        <div class="ussd-screen">
            <div class="ussd-line">*170#</div>
            <div class="ussd-line">{'🔴 SIMULATED TRANSACTION HOLD' if state['alert'] else '🟢 APPROVED'}</div>
            <div class="ussd-body">{state.get('message', '')}</div>
            <div class="ussd-prompt">{state.get('action_prompt', '')}</div>
        </div>
    """

    # 2. The warning banner, embedded INSIDE the screen (no stray </div>!)
    warning_html = ""
    if state["alert"]:
        warning_html = f"""
            <div class="phone-warning">
                <div class="warn-title">⚠️ FRAUD ALERT — SIKA AFONO AKENKAN</div>
                <div class="warn-body">{state.get('twi_msg', '')} {state.get('en_msg', '')}</div>
            </div>
        """

    # 3. ONE complete, correctly-nested phone string
    phone_html = f"""
        <div class="phone-frame">
            <div class="phone-status">
                <span>MTN · Ghana</span><span>LTE ▮▮▮▯ 🔋</span>
            </div>
            <div class="phone-screen">
                {screen_inner}
                {warning_html}
            </div>
            <div class="phone-caption">
                Victim handset (simulated — what the customer sees, in real time)
            </div>
        </div>
    """

    # 4. Render the WHOLE phone in ONE call, with HTML enabled
    st.markdown(phone_html, unsafe_allow_html=True)
```

**What this changes vs Kimi's version:**
- The warning is no longer a separate render call — it's a string *inside* the phone's HTML, so it visually sits within the phone frame.
- The extra `</div>` is gone; nesting is `frame > screen > (ussd + warning)` and `frame > caption`.
- A single `st.markdown(..., unsafe_allow_html=True)` renders everything as styled HTML.

> ⚠️ **Also check `app.py`:** if the phone is currently rendered like `st.write(render_mock_phone(...))` or `st.markdown(render_mock_phone(...))` (without the flag), change every such call to `st.markdown(render_mock_phone(...), unsafe_allow_html=True)`. The flag must be on **every** call that emits HTML.

> 💡 If after this fix the CSS still looks "flat" (Streamlit sometimes scopes `st.markdown` CSS), swap the final line to an isolated iframe render, which is bulletproof for custom CSS:
> ```python
> from streamlit.components.v1 import html as st_html
> st_html(phone_html, height=560)
> ```
> (Then move the `.phone-frame/.phone-warning/...` rules into a `<style>` block at the top of `phone_html`.)
